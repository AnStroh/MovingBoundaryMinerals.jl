# Changelog

All notable changes to `MovingBoundaryMinerals.jl` are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- Example D2: diffusion-limited crystal growth of olivine driven by a user-defined, non-monotonic temperature-time path (temperature may increase and decrease between user-specified nodes, unlike D1's monotonic cooling path). Optionally (`animate_sim = true`) saves a GIF of the composition-profile/phase-diagram evolution over the whole T-t path, via Plots.jl's `Animation`/`frame`/`gif`.
- A local, browser-based GUI (`GUI/`) for running single-crystal diffusion, moving-interface diffusion couple, and thermodynamically constrained growth/resorption models without writing Julia code: pre-filled forms with inline explanations of the less obvious parameters, cancellable background runs with an elapsed-time display and a live progress bar (`t / t_tot`), and downloadable results (plot at 300 dpi as PNG/PDF, raw profile data, and an `inputs.toml` recording every parameter for exact reproducibility) organized by a "Past runs" history page. See `GUI/README.md` and the [GUI documentation page](https://anstroh.github.io/MovingBoundaryMinerals.jl/dev/man/gui/).
- A package logo and favicon (`docs/src/assets/`), shown on the documentation site and in the README.
- Documentation: a [Getting Started](https://anstroh.github.io/MovingBoundaryMinerals.jl/dev/man/getting_started/) guide, an [Interpreting Output](https://anstroh.github.io/MovingBoundaryMinerals.jl/dev/man/interpreting_output/) page, and a [Quick Reference](https://anstroh.github.io/MovingBoundaryMinerals.jl/dev/man/quick_reference/) page; restored and expanded the General Remarks, Stefan Problem, and Digitization pages; added a proper bibliography via DocumenterCitations.jl; split the function reference into public API vs. internal helpers.
- `Stable` documentation badge, alongside the existing `Dev` badge.
- Documentation: [Boundary Conditions](https://anstroh.github.io/MovingBoundaryMinerals.jl/dev/man/boundary_conditions/) (the equations behind the outer Dirichlet/Neumann conditions and the three inner interface conditions — flux-balance, total mass-balance, and the thermodynamically constrained Stefan condition), [Mesh Refinement](https://anstroh.github.io/MovingBoundaryMinerals.jl/dev/man/mesh_refinement/) (the m-refinement and h-refinement grading equations behind each `RefineMethod`), and [Configuration Options](https://anstroh.github.io/MovingBoundaryMinerals.jl/dev/man/configuration_options/) (the switches that change which code path is used) pages; expanded Numerical Approach with the governing diffusion equation, the Arrhenius law, and the FEM/implicit-time discretization; expanded the Stefan Problem page with the interface-velocity equation and the `CompInt` lever-rule/domain-length relation.
- GUI: a **Delete all runs** button on the "Past runs" page, alongside the existing per-run **Delete** button, for clearing out `GUI/results/` without leaving the browser; both ask for confirmation first.
- GUI: every run now also saves `profiles.xlsx` and `profiles.jld2` (via XLSX.jl and JLD2.jl respectively) alongside the existing `.tab`/`inputs.toml` outputs — each bundles the initial/final profile data together with every input parameter and result into a single file, for users working in Excel or Julia. `inputs.toml` and both bundled exports now also carry the same small citation line already stamped on the plot and `.tab` files. (A `.mat` export via MAT.jl was tried and dropped: its only unconditional dependency is HDF5.jl, which pulls in four MPI implementations and AWS S3 client libraries for no reason a local single-array write needs — too heavy and failure-prone to install on the locked-down networks common in (geo)science/industry settings. `.xlsx` opens fine in MATLAB too.)
- GUI: an automated test suite (`GUI/test/`, run via `julia -t auto --project=GUI GUI/test/runtests.jl`), exercising every route in-process (no real server or browser) against a throwaway results directory — covers all three backends end to end, input validation, job cancellation, the "already running" conflict, and both delete endpoints. Wired into CI (`.github/workflows/GUI.yml`) on every change under `GUI/` or `src/`. `RESULTS_DIR` is now overridable via the `MBM_GUI_RESULTS_DIR` environment variable to make this possible; `app.jl`'s `main()` only runs when the file is launched directly, not when it's `include`d for testing.
- Documentation: [Benchmarks](https://anstroh.github.io/MovingBoundaryMinerals.jl/dev/man/benchmarks/) (every example tested against a closed-form analytical or semi-analytical solution — A1, A2, B1, B2, B4, B5, C1) and [Example Gallery](https://anstroh.github.io/MovingBoundaryMinerals.jl/dev/man/example_gallery/) (B6, B7, C2, D1 — realistic/illustrative output with no closed-form solution to compare against, kept separate from the benchmarks since they validate nothing) pages, each figure reproduced from [Stroh2025] with attribution.
- GUI: the thermodynamic growth mode now exposes every physically meaningful hardcoded value from `D1.jl`/`D2.jl` as a form field: the crystallographic angles `alpha`/`beta`/`gamma` and activation volume `deltaV` (anisotropic diffusion), the melt/fluid side's pre-exponential factor and activation energy `D0_right`/`Ea_right` (previously a fixed `exp(-7.92 - 26222/T)`, now reparametrized into the same `D0*exp(-Ea/(R*T))` form used for the crystal side, with defaults chosen to reproduce the original formula exactly), grid resolution (`nx_left`/`nx_right`) and `CFL`, and a "Total time" field that rescales the temperature-time path to a chosen duration without needing to hand-edit every row.
- GUI: thermodynamic growth runs now also save `path.tab`, the temperature-time path actually used, in the same `time [days], temperature [°C]` format the form's path field takes, so a run's path can be copied straight back in to reproduce or tweak it.
- GUI: server-side validation (`min`/`strict` bounds on every numeric field, geometry/resolution consistency checks) across all three modes, closing a gap where an invalid value (a negative or zero domain length, `CFL = 0`, `nx < 2`, ...) was only blocked by client-side HTML5 validation and could otherwise crash a background job with an unhandled, unhelpful error.
- GUI: a `GET /jobs/current` endpoint plus client-side polling on every page load, so reloading the page (or reopening the app window after accidentally closing it) while a simulation is still running reattaches its progress bar and **Cancel** button, instead of showing a blank idle form with no way to see progress or cancel.
- GUI: results pages handle missing/deleted result folders and dead-end navigation properly - a deleted run's results page shows a normal "not found" message with a link back instead of a bare 404, and download links (including the "Past runs" thumbnail) use the `download` attribute so clicking them doesn't navigate the browser window away with no way back (the GUI runs in a chromeless window with no address bar or back button).
- The package logo in the GUI's navigation bar (light/dark theme-aware, matching the existing toggle).
- Documentation: a troubleshooting tip for a `Failed to precompile Oxygen` error caused by multiple installed Julia versions, a note on reconnecting to the GUI after accidentally closing its browser window, and a known-good non-monotonic temperature-time path for the thermodynamic growth mode (matching `D2.jl`'s own default) alongside an explanation of what makes such a path fail (the bundled phase diagram is only valid over a limited temperature range, and its two composition curves cross at one particular temperature where interface velocity is undefined).
- Documentation: the thermodynamic growth mode's "What it covers" entry now says explicitly that it's fixed to the bundled olivine (Fe-Mg) phase diagram [DohmenChakraborty2007a](@cite), [DohmenChakraborty2007b](@cite) - not a general-purpose solver you can point at your own data through the form, since the CSV paths are hardcoded in `GUI/backends/thermo_growth.jl`.
- Documentation: the phase-diagram digitizing workflow ([Digitization](https://anstroh.github.io/MovingBoundaryMinerals.jl/dev/man/digitalization/)) now explicitly warns that `Y_BC` (the temperature axis bound passed to `digitizePlot`) must be in K, even though the source phase-diagram image is very likely labelled in °C - `digitizePlot` only ever sees pixel coordinates and has no idea what unit an image's printed axis is in, so typing the printed °C limits in directly would silently digitize and fit everything in the wrong unit.
- Documentation: [Example Gallery](https://anstroh.github.io/MovingBoundaryMinerals.jl/dev/man/example_gallery/) now includes `D2.jl`'s own template example (previously only referenced from the GUI docs) - the final composition/phase-diagram figure and an animation of the whole run.
- README: an "Examples" section near the top with animations of `D1` and `D2` (linear vs. non-monotonic cooling), linking to the Example Gallery for the full write-up.

### Changed
- GUI: the Thermodynamic growth mode's temperature-time path is now an arbitrary list of (time, temperature) points (one `time [days], temperature [°C]` pair per line) instead of a fixed start/end pair — a 2-point path reproduces `D1.jl`'s linear cooling exactly as before, but more points now also reproduce `D2.jl`'s non-monotonic path, which the GUI previously couldn't run at all.
- GUI: the citation line stamped on every plot, `.tab`, `inputs.toml`, `.xlsx`, and `.jld2` output now references the package's Zenodo software archive (doi:10.5281/zenodo.15535732) instead of the [Stroh2025](@cite) paper's DOI, since it's citing the specific software version a result was produced with, not the method paper.
- README: the "How to cite" section now also lists the Zenodo software DOI alongside the paper citation.
- GUI: removed the non-functional `rho` (density) field from the single-crystal form - it only ever fed the `MB_Error` mass-balance diagnostic, never the diffusion solve itself, so changing it had no effect on the actual result. Fixed to the same normalized value (`1.0`) `diffusion_couple` already uses.
- GUI: restored moving-interface (`V_ip != 0`, growth/resorption) support in the diffusion-couple mode - the regridding step was never called regardless of `V_ip`, so a nonzero interface velocity silently behaved as if it were `0.0`. Also exposed `CFL` and grid resolution (`nx_left`/`nx_right`), previously fixed.
- `D2.jl`'s default `Ri` (0.0001 -> 0.0005) and its default temperature-time path (see Fixed, below) - matched by the GUI's thermodynamic growth mode's own `Ri` default, for the same reason.

### Fixed
- **`D1.jl`, `D2.jl`, and the GUI's thermodynamic growth backend: the anisotropic diffusion weighting used `cos()` (radians) instead of `cosd()` (degrees) for the crystallographic angles `alpha`/`beta`/`gamma`, which are documented and used as degrees everywhere else.** `cosd(90) = 0` as intended, whereas `cos(90) ≈ -0.448`, so the two axes meant to be perpendicular to the modelled profile (and so contribute nothing) were picking up a spurious `cos(90)^2 ≈ 0.2` weight each. For the default `alpha=0, beta=90, gamma=90`, this overestimated the effective diffusion coefficient `D_l` by about 6.7% - **this affects `D1.jl`'s reproduction of Figure 10 in [Stroh2025](@cite)**; see the note on the [Example Gallery](https://anstroh.github.io/MovingBoundaryMinerals.jl/dev/man/example_gallery/) page.
- `D2.jl`: the interior/movie-frame plotting block's "(a)" panel label was drawn at a fixed y-position that assumed the panel's y-axis range only grows over the course of a run - true for `D1.jl`'s monotonic cooling, but a non-monotonic path can shrink that range and push the label outside the panel. Positioned as a fraction of the panel's own (already dynamic) range instead.
- `D2.jl`: the interior/movie-frame legend for the grey "current temperature" marker read `T(t_tot)` (the final plot's label) instead of `T(t)`.
- **`D2.jl`'s default temperature-time path could fail with `ArgumentError: Cannot proceed (Newton Failure)` after several hours, under the corrected `cosd()` physics.** The path's sharp corners (large slope changes packed into 3-day intervals) drive the interface velocity into a regime the regridder cannot keep up with. The new default (`Ri=0.0005` instead of `0.0001`, and a gentler fall/plateau/rise path instead of the old wiggle) completes the full 30 days in well under a minute; see the note above `D2.jl`'s function signature and the GUI documentation's non-monotonic-path tip for the full explanation.
- `D2.jl`: the "(a)"/"(b)" panel labels were positioned at fixed absolute coordinates (`x=0.015` mm, `x=1300`°C) that collided with the y-axis tick labels for domain/temperature ranges other than the original defaults (e.g. after the `Ri` change above). Both are now a fraction of their panel's own plotted range.
- `D2.jl`: panel (b)'s x-axis (`T [°C]`) could render an unreadable cluster of overlapping tick labels, since its range depends on the chosen T-t path and a 5-tick count hint doesn't always give evenly-spaced "nice" values. Explicit tick positions are used instead, with only every other one labelled (and never the one closest to the axis origin, which would collide with the y-axis "0.0" label).
- GUI: `GUI/test/test_progress_reporting.jl`'s `run_thermo_growth` case used a deliberately extreme path (50°C in 0.001 days, for CI speed) without pinning `Ri`, so it started failing with the same "Interface moved too fast" guard once the default `Ri` above changed; pinned to the pre-change `Ri=0.0001`, which this specific (unrealistic but harmless for a progress-reporting check) path is fine at.
- GUI: clicking **Cancel** appeared to need several clicks to take effect. The click was actually registered (and the run genuinely cancelled) every time - but the 1-second `renderRunning()` tick that updates the elapsed-time display kept rebuilding the whole status area, including a fresh Cancel button, which clobbered the "Cancelling..." feedback and made a successful click look like it had done nothing.
- GUI: every downloadable result (plot PNG/PDF, profile data, `.xlsx`/`.jld2`, and the "Open full results folder" link) 404'd on a normally-started server. `dynamicfiles` registers one route per file present in `GUI/results/` *when the server starts* - since that folder is empty at startup and every run's files are written well after, none of them ever got a route, and the folder link 404'd unconditionally (no run folder has an `index.html` for it to serve). Replaced with two routes that resolve the requested path fresh on every request instead. Existing tests never caught this because they only checked the files existed on disk, never fetched them over HTTP; `check_result_files` now does both.
- `D2.jl`: the interior plotting block (only ever exercised when `plot_sim`/`animate_sim` is enabled) passed the initial composition `C0` to `plot!` as a `1×n` row matrix instead of a vector, which Plots.jl rejects; fixed with `vec(C0)`.
- `D2.jl`: the final plotting block referenced `tpath`, a variable local to `D2()` that was never returned to the calling script, which would crash the script's default (`plot_end = true`) run at the very last plotting step; fixed by using the outer `t_user` instead, which holds identical values (`tpath = copy(t_user)` is never mutated).
- `CI.yml` no longer runs (and spuriously fails) on the `gh-pages` branch created by documentation deployment.
- A docstring-formatting bug (a stray blank line between the docstring and the `function` keyword) that silently dropped the docstrings of 13 exported functions, including `calculate_dt`, `save_figure`, and `h_refinement1`/`h_refinement2`.
- `MovingBoundaryMinerals.Benchmarks` functions (e.g. `analytical_sol_step_function`, `smith`, `rayleigh_fractionation`) are now properly reachable via `using MovingBoundaryMinerals` alone, instead of requiring a separate `using MovingBoundaryMinerals.Benchmarks`.
- Several thin/incomplete docstrings (missing arguments, missing units, incorrect type annotations) across `functions.jl`.
- Numerous spelling and grammar issues across the documentation and source comments.
- Documentation previously conflated the flux-balance interface condition with the (thermodynamically constrained) Stefan condition in several places (e.g. describing the interface velocity `V_ip` as solved-for in the flux-balance/mass-balance cases, where it is actually a prescribed input; and the `Residual` diagnostic as applying to all moving-interface examples rather than just the Stefan-condition family).

### Removed
- Dead package exports (`digitise_plot`, `ndgrid`, `lasaga`, `preallocations`) that referenced functions not defined anywhere in the package.
- Codecov badge from the README.

## [1.0.0] - 2025-12-02

### Added
- h-refinement grid strategies (`h_refinement1`, `h_refinement2`) as alternatives to m-refinement, selectable via `RefineMethod`.
- DOI badge and citation information in the README.

### Changed
- `nPoints` for h-refinement can now be given as a single number (both sides equal) or as `[left right]`.
- General code cleanup and example fixes.

## [0.1.0] - 2025-05-29

Initial public release: diffusion-couple and moving-boundary (Stefan) solvers, with benchmarked examples (A, B, C series) and the thermodynamically constrained crystal-growth example D1.
